TurboQuant

How to compress a 384-dimensional vector into a handful of bytes — and still find what you're looking for.

Step 1: QJL Compression 1 bit/dim

Quantized Johnson-Lindenstrauss — a fast fingerprint for vectors

Original Vector (384 floats = 1,536 bytes)
Each cell is a 32-bit float like 0.42, -0.17, 0.88 ...
↓
Multiply by random matrix R
R is a fixed Gaussian matrix generated from a seed — same seed = same R everywhere
↓
Keep only the sign: positive → 1, negative → 0
↓
Compressed: 384 bits = 48 bytes
32x smaller! Each dimension is now a single bit.
Comparing two vectors = counting different bits (Hamming distance)

Vector B

Similar vectors in the original space share most sign bits, so low Hamming distance ≈ high cosine similarity. The CPU can compute this with a single XOR + popcount — blazing fast.

Step 2: PolarQuant 4-bit angles + 8-bit radii

Polar coordinate compression — more bits, more accuracy

How PolarQuant works
1. Rotate the vector
Apply a random orthogonal rotation (preserves distances, decorrelates dimensions)
↓
2. Pair adjacent dimensions
Group into 192 pairs: (d0,d1), (d2,d3), (d4,d5) ...
↓
3. Convert each pair to polar coordinates
(x, y) → (r, θ) where r = sqrt(x²+y²), θ = atan2(y, x)
Each dot is one (x,y) pair plotted in 2D. The grid shows quantization bins.
↓
4. Quantize
Angles (4-bit = 16 levels)
Radii (8-bit = 256 levels)
192 angle nibbles (96 bytes) + 192 radii bytes = 288 bytes per vector

Why two stages? QJL is extremely fast (XOR + popcount on packed bits) but approximate. PolarQuant is more accurate but slower. By using QJL to eliminate 98% of candidates first, we only run the expensive PolarQuant comparison on a small set — getting the best of both worlds.
