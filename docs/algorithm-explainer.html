TurboQuant

How to compress a 384-dimensional vector into a handful of bytes — and still find what you're looking for.

Step 1: QJL Compression 1 bit/dim

Quantized Johnson-Lindenstrauss — a fast fingerprint for vectors

Original Vector (384 floats = 1,536 bytes)
Each cell is a 32-bit float like 0.42, -0.17, 0.88 ...
↓
Multiply by random matrix R
R is a fixed Gaussian matrix generated from a seed — same seed = same R everywhere
↓
Keep only the sign: positive → 1, negative → 0
↓
Compressed: 384 bits = 48 bytes
32x smaller! Each dimension is now a single bit.
Comparing two vectors = counting different bits (Hamming distance)

Similar vectors in the original space share most sign bits, so low Hamming distance ≈ high cosine similarity. The CPU can compute this with a single XOR + popcount — blazing fast.

Step 2: TurboQuant_mse 3 bits/dim

Optimal scalar quantization — provably near-optimal MSE distortion

How TurboQuant_mse works
1. Normalize & rotate the vector
Store the L2 norm separately, then multiply by a random orthogonal matrix Q (seeded)
After rotation, each coordinate ≈ N(0, 1/d) — nearly independent in high dimensions
↓
2. Quantize each coordinate with a Lloyd-Max codebook
For 3-bit: 8 precomputed optimal centroids for N(0, 1/√d). Each coordinate snaps to its nearest centroid.
Number line showing 8 centroids (dots). Values snap to the nearest centroid.
↓
3. Pack 3-bit indices
384 × 3 bits = 144 bytes + 4 bytes norm = 148 bytes per vector (10x smaller than float32!)
Why is this near-optimal? The rotation makes coordinates nearly independent and Gaussian. The Lloyd-Max quantizer is optimal for a known distribution. MSE distortion ≤ 2.7× the information-theoretic lower bound (Theorem 1, Zandieh et al. 2025).
Search trick: Since Q is orthogonal, ⟨x, y⟩ = ⟨Qx, Qy⟩. Similarity is computed directly from codebook centroids — no matrix multiply at search time, just table lookups.

Why two stages? QJL is extremely fast (XOR + popcount on packed bits) but approximate. TurboQuant_mse is more accurate but slower. By using QJL to eliminate 98% of candidates first, we only run the expensive TurboQuant_mse comparison on a small set — getting the best of both worlds.
